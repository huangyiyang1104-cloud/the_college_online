# 5.Python后端项目开发规范

1. 开发语言：Python
2. 后端技术栈：FastAPI + SQLChrme+ MySQL + Redis + MinIO
3. 类名使用 snake_case，例如 `test_service`。
4. 方法名、变量名使用 python规范。
5. 常量使用大写下划线形式，例如 `DEFAULT_PAGE_SIZE`。
6. 命名应清晰表达业务意图，避免使用含义模糊的缩写。
7. 请求参数必须进行必要的格式、范围和业务校验。
8. 数据库操作优先使用 SQLAlchemy ，复杂查询可根据实际需要使用自定义 SQL。
9. 禁止在循环中无必要地执行大量单条查询，避免产生 N+1 查询问题。
10. 使用统一异常处理机制，避免在各个 API 中重复编写异常捕获代码。
11. 业务异常应携带清晰、可识别的错误信息或错误码。
12. 不得向前端返回 SQL 详情、堆栈信息、内部路径、密钥等敏感信息。
13. 代码注释应简洁、准确，重点说明业务意图、复杂逻辑和关键设计原因，避免冗余注释。





# 6.Vue3前端项目开发规范

1. 前端技术栈：Vue 3 生态，管理端使用 Element Plus 组件库。
2. 组件开发优先采用 Composition API 和 `<script setup>`。
3. 组件、方法及变量命名应清晰表达业务意图，避免使用含义模糊的缩写。
4. 页面结构与交互应符合已确认的页面原型和业务设计，不得擅自修改核心功能和布局。
5. 页面应保持整体风格统一，布局清晰、层次分明、视觉美观、大气，并兼顾常用屏幕尺寸的适配。
6. 表单应进行必要的参数校验，并提供清晰的错误提示、提交状态和操作反馈。
7. 后端接口调用应统一封装和管理，遵循既定的 API 规范，避免在页面中重复编写请求逻辑。
8. 路由守卫只负责前端导航控制，真正的身份认证和接口权限校验必须由后端执行。
9. 应合理处理数据加载中、请求失败、数据为空等状态，避免页面出现异常或无反馈的情况。
10. 不得在前端代码中暴露 API 密钥、服务端凭证等敏感信息。
11. 代码注释应简洁、准确，重点说明业务意图、复杂逻辑和关键设计原因，避免冗余注释。
