## 1. 项目主要功能

云枢智学是一个双端在线学习平台：**学员端**把"学课程、刷题自测、AI 面试"串成一条闭环，**管理端**由运营零代码维护全部内容（含面试资料库）。

### 1.1 学员端（C 端）

| 序号 | 功能 | 说明 |
|---|---|---|
| C-1 | 注册登录 | 手机号 + 短信验证码注册，手机号 + 密码登录；除登录注册外全部页面需登录 |
| C-2 | 学科与课程节点图 | 选学科 → 按学习顺序线性排列的课程节点图；点节点跳转 B 站 |
| C-3 | 学习进度 | 点击节点记访问流水；学员手动**点亮**节点；学科完成率由此聚合 |
| C-4 | 刷题练习 | 选学科组整卷，四类题型；一次性提交后出整卷结果与得分 |
| C-5 | 错题本 | 仅收客观题错题，重做答对自动移出；支持列表内直接重做 |
| C-6 | AI 面试（学科） | 选学科，从公共面试资料库检索出 5 题，语音 / 打字双通道作答，每题限追 1 次 |
| C-7 | 简历面试 | 上传 PDF 简历存 OSS，解析切分后按简历内容出题，重点针对项目经历 |
| C-8 | 面试报告 | 总分 + 逐题得分与 AI 点评，标注每题来源与作答方式 |
| C-9 | 记录与个人中心 | 学习记录、面试记录、个人信息查看与编辑 |

### 1.2 管理端（B 端）

| 序号 | 功能 | 说明 |
|---|---|---|
| B-1 | 数据看板 | 仅学员规模与活跃：注册数、新增趋势、日 / 周活跃（近 7 天） |
| B-2 | 课程内容维护 | 学科 → 课程 两级结构维护，学习顺序、B 站地址、上下架、课程 Excel 导入 |
| B-3 | 刷题题库管理 | 按学科维护判断 / 单选 / 多选 / 简答；简答录参考答案与解析；Excel 导入 |
| B-4 | 面试资料库 | 上传 md / pdf，转 Markdown 后切分入库；处理状态、失败重试、删除、RRF 检索测试 |
| B-5 | 学员管理 | 学员列表与点亮课程数，启用 / 禁用 |
| B-6 | 系统用户管理 | 后台账号与角色（超管 / 运营），内置超管不可删除与停用 |
| B-7 | 操作日志 | 记录后台关键操作，含变更前后快照 |

### 1.3 横切能力（由现有需求归纳，不是新增功能入口）

| 编号 | 能力 | 被谁使用 |
|---|---|---|
| S-1 | 认证与权限（学员登录态、后台两角色、页面与模块级拦截） | 全部模块 |
| S-2 | 内容与资料处理（B 站链接、Excel 导入解析与校验、PDF 转 Markdown、切分） | B-2 / B-3 / B-4 / C-7 |
| S-3 | 检索与出题（向量召回 + 关键词召回 + RRF 融合 + 生成题目） | C-6 / C-7 / B-4 检索测试 |
| S-4 | AI 判分与点评（简答判分、面试评分与追问、报告汇总） | C-4 / C-6 / C-7 / C-8 |
| S-5 | 语音通道（录音、识别、合成） | C-6 / C-7 |
| S-6 | 短信验证码下发与校验 | C-1 |

## 2. 功能模块划分

划分原则：**按学员可感知的业务能力切块**，管理端按"一棵内容树 + 两类资料 + 两类账号"切块；横切能力不单独设菜单，作为模块间共用的能力被引用。

### 2.1 学员端模块

| 模块 | 职责（一句话） | 包含功能点 | 明确不负责 | PRD | 原型路由 |
|---|---|---|---|---|---|
| **C1 账号与认证** | 确认"你是谁、能否进入" | 手机号注册（验证码 + 设密码）、手机号密码登录、退出、登录态拦截 | 密码找回、第三方登录 | 4.1 | `#/login` |
| **C2 学科与课程节点图** | 组织"学什么、按什么顺序学" | 首页（欢迎区 + 学科入口与进度 + 继续学习 + 最近学习）、学科列表、**课程节点图（线性顺序、点亮状态、推荐下一课）**、点击节点跳 B 站 | 不做站内播放、不采集观看时长与完播、不做阶段分层 | 4.3 | `#/home` `#/subject/:id` |
| **C3 学习进度** | 记录"学到哪了" | 访问流水写入、**手动点亮节点**、学科完成率聚合 | 不做自动进度识别（无完播采集） | 4.4 | 内嵌于 C2 页面与学习记录 |
| **C4 刷题练习** | 用整卷验证学科掌握度 | **按学科选卷**、四类题型作答、一次性提交、客观题即时判分、简答 AI 对照参考答案判分、答卷结果页（判分中 → 出结果）、历史答卷回看 | 不做限时、不做逐题即判模式 | 4.5 | `#/practice` `#/practice/run/:subjectId` `#/paper/:id` |
| **C5 错题本** | 沉淀错题并支持重做 | 客观错题收录、答对自动移出、列表内重做（多选可多选）、手动移除；**重做复用 C4 的判分规则，本模块不单独实现判定** | 不收简答题；不做按知识点归类 | 4.6 | `#/wrong-book` |
| **C6 AI 面试（学科）** | 用 AI 检验学科掌握度 | 选学科、**以学科检索关键词取题**、语音 / 打字双通道作答、单题限追 1 次、15 分钟计时、每日 3 次限流、会话落库 | 不做结构化面试题库 | 4.7 | `#/interview` `#/interview/live` |
| **C7 简历面试** | 围绕简历（重点项目）做面试 | PDF 上传与解析状态展示、重新上传、按简历出题（项目 ≥ 3 题）、复用面试会话；解析链路复用 S-2 | 后台不可查看简历内容、不允许多份并存 | 4.9 | `#/resume-interview` |
| **C8 报告与记录** | 让学员看到结果并回看 | 面试报告（总分 + 逐题点评 + 来源 + 作答方式）、面试记录列表、学习记录、个人信息编辑 | 不做分维度评分、不做薄弱项与提升建议、不做掌握度独立页 | 4.8 / 4.10 | `#/interview/report/:id` `#/records/learning` `#/records/interview` `#/profile` |

> C6 与 C7 共用同一套"面试会话 → 追问 → 评分 → 报告"能力，差异只在**出题来源**（公共资料库检索 vs 个人简历库检索），按 Q1 结论保持两个并列模块。

### 2.2 管理端模块

| 模块 | 职责 | 包含功能点 | 明确不负责 | 原型路由 |
|---|---|---|---|---|
| **B1 数据看板** | 给运营看规模与活跃 | 累计注册、今日新增、今日活跃、近 7 日新增趋势图 | 不做学习 / 刷题 / 面试指标、不做题目错误率、不做学员掌握度 | `#/admin/dashboard` |
| **B2 课程内容** | 维护学科与课程这棵树 | 学科 Tab、学科**新增 / 编辑 / 上下架 / 删除**、学科检索关键词、课程列表、**学习顺序调整**、B 站地址、**课程新增 / 编辑 / 上下架 / 删除**、课程 Excel 导入 | 不拆成"学科 / 课程"两个菜单；不做阶段分层 | `#/admin/content` |
| **B3 刷题题库** | 维护刷题题目 | **按学科**新增四类题型、**编辑题干 / 答案 / 解析 / 分值**、正确答案与简答参考答案、Excel 导入（预览校验后入库）、删除 | 不做题型转换（改题型等同于重录） | `#/admin/questions` |
| **B4 面试资料库** | 维护面试出题的原始资料 | md / pdf 上传、处理链路说明、文档列表（类型 / 大小 / 上传时间 / **状态**）、**解析失败可重新处理**、删除、RRF 检索测试 | 不维护结构化面试题、不按学科归档 | `#/admin/interview` |
| **B5 学员管理** | 查看学员账号与规模 | 学员列表（手机号、昵称、注册时间、**点亮课程数**、状态）、启用 / 禁用 | 不展示简历、不展示掌握度与刷题结果 | `#/admin/students` |
| **B6 系统用户管理** | 维护后台账号 | 账号新增、角色（超管 / 运营）、启用 / 停用、删除（内置超管除外） | 不做独立角色管理模块、不做按钮级权限 | `#/admin/users` |
| **B7 操作日志** | 追溯后台改动 | 记录新增 / 编辑 / 上下架 / 删除 / 导入等操作，含变更前后快照 | 记录范围待确认 | `#/admin/logs` |

## 3. 模块之间的关系

### 3.1 依赖方向

```
                   ┌────────── B 端（内容生产） ──────────┐
                   │  B2 课程内容（学科 + 课程节点）       │
                   │  B3 刷题题库      B4 面试资料库       │
                   └──────┬───────────────────┬──────────┘
                          │ 内容/题目被消费    │ 资料被检索
                          ▼                   ▼
  C1 账号 ──► C2 学科与课程节点图 ──► C3 学习进度（点亮）
                    │
                    ├──► C4 刷题练习 ──► C5 错题本
                    │
                    └──► C6 学科面试 ──┐
                         C7 简历面试 ──┴──► C8 报告与记录
```

| 关系 | 说明 |
|---|---|
| B2 → C2 / C3 | 学科与课程由 B2 生产，C2 只读消费；课程下架后 C 端不展示但历史记录保留 |
| B2 → C4 / C6 | 学科是组卷与面试的范围依据（`subject_id`） |
| B3 → C4 / C5 | 题目按学科挂载；C4 组卷来源、C5 错题来源均为 B3 的题库 |
| B4 → C6 | 学科面试的题目由公共资料库检索片段生成，**不存在结构化面试题库** |
| C7 → S-2 | 简历**复用**公共资料库的同一套解析链路，只是数据存入**个人简历库**与公共库隔离 |
| C4 → C5 | 整卷提交后，客观题错误写入错题本；简答题不写入 |
| C6 / C7 → C8 | 面试会话结束后产出报告，进入面试记录 |
| B5 / B7 ← 全后台 | 学员数据来源于 C 端注册与学习行为；操作日志由各后台写操作触发 |
| 后台 ↔ 掌握度 | **不连通**：学员掌握情况仅在 C 端可见，后台不提供任何掌握度或刷题统计 |

### 3.2 跨模块共享的三类数据

1. **内容数据**：学科、课程、题目（B 端写，C 端读）。
2. **资料数据**：公共面试资料与其切片（B 端写，C6 读）；个人简历与其切片（C7 写读，后台不可见）。
3. **学员行为数据**：访问流水、点亮状态、答卷、错题、面试记录与报告（C 端写读；后台只读聚合后的规模与活跃）。

## 4. 核心业务流程

### 4.1 学习闭环（主流程）

```
C1 登录 → C2 选学科 → 看到按顺序排列的课程节点图 → 点击节点跳转 B 站
        → 回到平台点亮该节点 → C3 重算学科完成率 → 节点图高亮"推荐下一课"
```

- 进度只来自**手动点亮**，平台不采集观看时长。
- 节点图是**线性顺序**，不做前置解锁，学员可任意点任一节点。
- 课程已下架时：C 端节点图不再展示，但已有的访问与点亮状态不失效。
- 学科完成率 = 已点亮课程数 ÷ 学科课程总数，实时计算。

### 4.2 刷题与错题复盘

```
C4 选学科 → 从该学科题池组整卷 → 逐题作答 → 一次性提交
   ├─ 客观题：即时判对错 + 解析
   └─ 简答题：AI 对照参考答案判分 → 结果页先"判分中"后出"得分 + 点评"
→ 整卷结果页（总分、逐题明细）
   ├─ 客观错题 → 写入 C5 错题本
   └─ 简答题 → 不进入错题本
→ C5 中重做错题：答对自动移出，答错累计错误次数
```

### 4.3 学科 AI 面试

```
C6 选学科 → 学科关键词做检索 query → 向量召回 + 关键词召回 → RRF 融合 → 取 TopN 片段
→ 模型生成 5 道题 → 逐题：AI 提问 → 学员选择语音 / 打字作答 → 可追问 1 次 → 评分
→ 5 题结束（或 15 分钟到）→ C8 报告（总分 + 逐题点评 + 来源文档 + 作答方式）
```

- 每日 3 次为学科面试与简历面试**共享**的额度，发起即扣、不退还。
- 切片不带学科标签，同一片段可被多个学科命中，因此题目可能跨学科复用。

### 4.4 简历面试

```
C7 上传 PDF → 服务端存 OSS → 转 Markdown → 切分 → 向量化（个人简历库）
→ 展示解析出的项目经历 → 发起面试：项目相关 ≥ 3 题 + 技能 / 意向 2 题
→ 复用 4.3 的会话与评分链路 → C8 报告（来源标注为简历中的项目 / 技能）
```

- 解析链路复用公共资料库的同一套能力，仅数据存入个人简历库。
- 重新上传简历即替换旧简历，旧切片与向量随之失效。
- 后台不提供简历原文与解析内容的查看入口。

### 4.5 内容运营流程

```
B2 建学科 → 维护检索关键词 → 按学习顺序录课程（B 站地址）／导入课程 Excel
→ B3 按学科录题或导入题库 Excel
→ B4 上传面试资料（md / pdf）→ 转 md → 切分入库 → 用「检索测试」验证出题效果
→ B1 看板看规模与活跃 → B7 操作日志留痕
```

- 全部内容均为"录完即上线"，只有上架 / 下架两态，无审核流。

| **Q14** | **节点图连接方式** | **纯线性顺序（`sort_order`）** | 不需要依赖边表；"推荐下一课"取第一个未点亮节点 |

| **Q16** | **取消阶段后题目挂哪一层** | **题目挂学科，整学科组卷** | `question.subject_id`、`exam_paper.subject_id` |
| **Q17** | **删学科时子级怎么处理** | **有未删除课程则禁止删除** | 删除接口需先校验课程数量 |

### 5.2 仍需在开发前定量

整卷是否限时、面试异常处理、资料库切片下限、操作日志范围、记录保留、可改字段、限流与验证码口径、导入校验、切分与检索参数、出题方式、简历异常与存储清理——均不影响模块划分，详见 `docs/PRD.md` 第 7 节。

> 组卷规则（每套 20 题，判断 4 / 单选 8 / 多选 4 / 简答 4，不足按实际题量）与面试总分口径（各题平均、四舍五入）已于第四阶段确认，落在 PRD §4.5 / §4.8 与 `04.API接口设计.md`。

## 6. 本阶段结论

1. 系统划分为 **C 端 8 个模块 + B 端 7 个模块 + 6 项横切能力**，通过"内容 → 消费"与"行为 → 记录"两条主线相连。
2. **学科是唯一组织轴**：课程、题目、答卷、面试范围全部挂在学科下，学习顺序靠 `course.sort_order`，进度靠"点亮"。
3. 后台与学员掌握度**刻意不连通**：看板只有规模与活跃，B4 只维护原始资料，B5 只看账号与点亮课程数。
4. 面试仍是复杂度最高的模块：出题靠检索不靠题库，作答有语音与打字双通道，报告要标注来源。
5. Q1–Q17 已全部确认；无剩余设计级待确认项，实施细节见 PRD 第 7 节。
