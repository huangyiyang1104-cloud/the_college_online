## 1. 全局约定

### 1.1 基础信息

| 项 | 约定 |
|---|---|
| Base URL | `/api/v1`（学员端与后台共用前缀，后台统一在 `/api/v1/admin` 下） |
| 前端部署 | 学员端 `/`、管理端 `/admin`（两个独立前端工程，同域部署）；两端各自持有对应 `aud` 的 token，接口前缀不随页面路径变化 |
| 传输 | HTTPS，`Content-Type: application/json; charset=utf-8`；上传为 `multipart/form-data` |
| 路径风格 | 资源用**名词复数**（`/subjects`、`/papers`），不用动词；动作语义交给 HTTP 方法 |
| 版本 | 路径版本号；不兼容变更升 `v2` |
| 标识符 | 所有 `id` 在 JSON 中**序列化为字符串**（库为 BIGINT，避免前端精度丢失） |
| 时间 | ISO-8601 UTC，如 `2026-11-01T09:12:33Z`（库内 DATETIME 存 UTC，出参不做时区转换） |
| 字段命名 | **snake_case，与数据库完全一致**（已确认；前端在 api 层做一次映射，评审时可直接对照 `schema.sql`） |
| 金额/分数 | 数值型（`10.00`），不使用字符串 |
| 枚举 | 出参用数字 + 文档含义；入参也用数字 |

### 1.2 认证与权限

**双 token 方案**

| 项 | 约定 |
|---|---|
| access_token | JWT，有效期 30 分钟，`Authorization: Bearer <token>` |
| refresh_token | 不透明随机串（同时落 Redis `auth:refresh:{jti}` → `{user_id, audience}`），有效期 7 天 |
| 刷新 | `POST /auth/tokens` 传入 refresh_token 换发新 token，**轮换**：颁发新 access + 新 refresh，旧 refresh 立即失效 |
| 退出 | 删除该 jti；access 因短时效自然过期 |
| 禁用立即失效 | Redis 记 `auth:revoked:{audience}:{user_id}` = 时间戳，校验 access 时若 `iat < revoked_at` 判失效（不改表结构） |
| 令牌载荷 | `sub`(用户 id)、`aud`(`student` / `admin`)、`role`(`student` / `super_admin` / `operator`)、`jti`、`exp`、`iat` |
| 敏感信息 | token 一律走 header 或请求体，**不得放 URL 查询参数** |

**权限矩阵**

| 接口分组 | 学员 | 运营 | 超管 |
|---|---|---|---|
| `/api/v1/**`（除 `/admin/**`） | ✅ | ❌ | ❌ |
| `/api/v1/admin/**`（除系统用户） | ❌ | ✅ | ✅ |
| `/api/v1/admin/users/**`（系统用户） | ❌ | ❌ | ✅ |

- 学员 token 访问 `/admin/**` → `403 / 10003`；后台 token 访问学员接口 → 同理。
- 教练/越权统一返回 403，不区分"不存在"与"无权限"，避免探测。

### 1.3 统一响应结构

**成功**

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

**分页**（`data` 固定四字段，`page` 从 1 开始，`page_size` 默认 20、上限 100）

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [],
    "total": 128,
    "page": 1,
    "page_size": 20
  }
}
```

**失败**

```json
{
  "code": 10001,
  "message": "参数校验失败",
  "data": {
    "fields": [
      { "field": "phone", "reason": "手机号格式不正确" }
    ]
  }
}
```

规则：
- HTTP 状态码表达语义（200/201/204/400/401/403/404/409/413/422/429/500/503/504），**不把所有错误都返回 200**。
- `code = 0` 仅表示成功；失败时 `code` 为业务码，`message` 可直接展示。
- `204 No Content` 无响应体。

### 1.4 参数校验规则

| 类型 | 规则 |
|---|---|
| 手机号 | `^1\d{10}$` |
| 密码 | 6–32 位，至少含字母与数字 |
| 验证码 | 6 位数字（由阿里云生成下发，后端不掌握明文），有效期 5 分钟，同一手机号 60 秒内不可重发、单日上限 10 次 |
| 字符串 | 标题类 ≤ 255、名称类 ≤ 64、简介类 ≤ 512、文本正文 ≤ 20000 |
| 分值 | 0 < score ≤ 100，保留两位小数 |
| 分页 | `page ≥ 1`、`1 ≤ page_size ≤ 100` |
| 枚举 | 越界直接 400，不做静默兜底 |
| 数组 | 标签 ≤ 10 个（单个 ≤ 32 字符）、关键词 ≤ 20 个（单个 ≤ 64 字符）、`course_ids` ≤ 500、`answers` ≤ 100 |
| 文件 | 简历仅 `application/pdf`；资料 `application/pdf` / `text/markdown`；单文件 ≤ 10 MB |

### 1.5 错误码规范

段位：`10xxx` 通用、`20xxx` 账号、`30xxx` 内容、`40xxx` 刷题、`50xxx` 面试、`60xxx` 文件、`70xxx` AI 依赖。详见第 6 节。

### 1.6 幂等与重复提交

| 场景 | 处理 |
|---|---|
| 点亮节点 | `PUT` 幂等，重复调用返回同一 `completed_at` |
| 取消点亮 | `DELETE` 幂等，未点亮也返回 204 |
| 提交答卷 | `POST /papers` 每次创建一份新答卷（允许同学科多次练习）；不支持重复提交同一份答卷 |
| 面试作答 | 同一 `question_index` 重复提交**覆盖**原答案（便于纠正语音识别错误），`score` 以最后一次为准（已确认） |
| 导入确认 | `PATCH .../course-imports/{id}` 置 `confirmed`：已确认或已过期返回 409 / `30004` |

### 1.7 限流

| 对象 | 限制 | 超限返回 |
|---|---|---|
| 短信验证码 | 同号 60 秒 1 条、单日 10 条 | 429 / `20006` |
| 登录 | 同号连续失败 5 次锁 15 分钟 | 429 / `20007` |
| 学科/简历面试 | 每日 3 次，**发起即扣、不退还** | 429 / `50001` |
| 判分与出题 | 由服务端队列控制并发，不对外暴露 | — |

### 1.8 实时语音通道

`api-rules` 2.5 规定敏感信息不得进入 URL，因此**令牌不拼在 WS 地址上**，改用一次性票据 + `Sec-WebSocket-Protocol` 子协议头传递：

1. `POST /api/v1/interviews/{id}/ws-tickets` 获取 `ticket`（有效期 60 秒、一次性）。
2. 握手：`new WebSocket('wss://<host>/api/v1/ws/interviews/{id}', ['yunshu.v1', ticket])`，服务端从 `Sec-WebSocket-Protocol` 取票据校验，成功时回选 `yunshu.v1`；失败以 1008 关闭。
3. URL 上**不带任何凭证**，避免出现在网关日志与浏览器 Referer 中。
4. 上行：音频分片（PCM/Opus 二进制帧）；下行：`partial` 转写、`final` 转写、`error`。

> 文本作答与最终结果仍走 HTTP（`POST .../answers`），WS 只负责语音流转写，二者共用同一套评分口径。

## 3. 学员端接口

### 3.1 C1 账号与认证

#### POST /api/v1/auth/sms-codes

发送注册验证码。权限：公开。

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| phone | body | string | 是 | 11 位手机号 |
| scene | body | string | 是 | 固定 `register`（后续找回密码可扩展） |

响应 `200`：`{"code":0,"data":{"expires_in":300,"resend_after":60}}`

规则：
- **通道已定**：走阿里云号码认证服务（`dypnsapi`）的「测试手机号码」，短信真实下发到白名单号码、不计费；项目全程使用该通道，不切换真实计费通道。
- **白名单前置校验**：手机号不在 `.env` 的 `AUTH_TEST_PHONES` 名单内时，直接返回 `403 / 20008`（"当前仅支持测试号码"），**不发起阿里云调用**。本地名单与阿里云控制台名单需人工保持一致；若云端返回"号码不在名单"，同样映射为 `20008`。
- 手机号已注册返回 `409 / 20001`；触发频控返回 `429 / 20006`（同号 60 秒 1 条、单日 10 条）。
- **校验方式（按实测修正）**：阿里云模板里的 `${code}` 需**调用方自己传入**，平台不会自动生成。因此流程为：服务端生成 6 位随机码 → 以 `TemplateParam={"code":"…","min":"5"}` 下发 → 明文写入 Redis（`sms:code:{phone}`，TTL = 有效期）→ 注册时本地比对，**成功后立即删除**（防重放）。不再调用 `CheckSmsVerifyCode`。
- 验证码不落 MySQL；Redis 另存发送频控计数（`sms:cd:{phone}` 冷却、`sms:day:{phone}:{yyyymmdd}` 当日累计）。
- 另一层限频在阿里云侧（`biz.FREQUENCY`），比本地 60 秒更严格，命中时映射 `429 / 20006`。

#### POST /api/v1/auth/register

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| phone | body | string | 是 | 手机号 |
| code | body | string | 是 | 6 位短信验证码（提交后由 `CheckSmsVerifyCode` 云端判定） |
| password | body | string | 是 | 6–32 位，字母 + 数字 |

响应 `201`：

```json
{ "code": 0, "data": {
  "access_token": "…", "refresh_token": "…", "expires_in": 1800,
  "user": { "id": "1", "phone": "13800000000", "nickname": "", "city": "", "created_at": "2026-11-01T09:12:33Z" }
}}
```

规则：手机号不在测试白名单 `403 / 20008`；验证码经 `CheckSmsVerifyCode` 判定不通过或已过期 `400 / 20002`；手机号已注册 `409 / 20001`；注册成功即登录并写 `user_login_log`。

#### POST /api/v1/auth/login

| 参数 | 位置 | 类型 | 必填 |
|---|---|---|---|
| phone | body | string | 是 |
| password | body | string | 是 |

响应 `200`：同注册（不含 `user.created_at` 之外的新字段）；写 `user_login_log`、更新 `user.last_login_at`。
错误：`401 / 20003`（手机号或密码错误，不区分是哪一项）、`403 / 20004`（账号禁用）、`429 / 20007`。

#### POST /api/v1/auth/tokens

| 参数 | 位置 | 类型 | 必填 |
|---|---|---|---|
| refresh_token | body | string | 是 |

响应 `200`：`{access_token, refresh_token, expires_in}`，旧 refresh 立即失效。失效/过期 `401 / 20005`。

#### POST /api/v1/auth/logout

权限：学员。响应 `204`。删除当前 refresh jti。

#### GET /api/v1/users/me

响应 `200`：

```json
{ "code": 0, "data": {
  "id": "1", "phone": "13800000000", "nickname": "小北", "city": "杭州",
  "status": 1, "created_at": "2026-10-02T08:00:00Z",
  "stats": { "completed_courses": 6, "paper_count": 3, "wrong_count": 2, "interview_count": 1 }
}}
```

> `stats` 为聚合计算字段（对应 `course_completion` / `exam_paper` / `wrong_question` / `interview_session` 计数），非库字段，见 7.2。

#### PATCH /api/v1/users/me

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| nickname | body | string | 否 | ≤ 64 |
| city | body | string | 否 | ≤ 64 |

响应 `200`：返回更新后的用户对象。手机号不可修改（PRD 假设项）。

### 3.2 C2 学科与课程节点图

#### GET /api/v1/home

首页聚合。权限：学员。

响应 `200`：

```json
{ "code": 0, "data": {
  "subjects": [
    { "id": "1", "name": "AI 全栈开发", "icon": "🧠", "description": "…",
      "course_count": 8, "completed_count": 3, "progress_percent": 38,
      "next_course": { "id": "12", "title": "HTTP 协议与接口设计基础" } }
  ],
  "recent_visits": [
    { "course_id": "12", "course_title": "HTTP 协议与接口设计基础",
      "subject_id": "1", "subject_name": "AI 全栈开发",
      "visited_at": "2026-11-01T08:20:00Z", "is_completed": false }
  ]
}}
```

规则：只返回 `status=1` 且未删除的学科与课程；`course_count`/`completed_count`/`progress_percent`/`next_course` 均为计算字段；`recent_visits` 取最近 3 条。

#### GET /api/v1/subjects

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| page | query | int | 否 | 默认 1 |
| page_size | query | int | 否 | 默认 20 |

响应：分页，条目含 `id/name/icon/description/course_count/completed_count/progress_percent`。

#### GET /api/v1/subjects/{id}

学科详情 + 节点图。响应 `200`：

```json
{ "code": 0, "data": {
  "id": "1", "name": "AI 全栈开发", "icon": "🧠", "description": "…",
  "course_count": 8, "completed_count": 3, "progress_percent": 38,
  "recommended_course_id": "12",
  "nodes": [
    { "id": "11", "sort_order": 1, "title": "Python 环境搭建与基础语法",
      "description": "…", "duration_minutes": 52, "bilibili_url": "https://www.bilibili.com/video/BV…",
      "is_completed": true, "completed_at": "2026-10-30T12:00:00Z" }
  ]
}}
```

规则：`nodes` 按 `sort_order` 升序，只含上架课程；`recommended_course_id` = 第一个未点亮节点，全亮则为 `null`。

#### POST /api/v1/courses/{id}/visits

记录一次访问流水。**按天去重**（已确认）：同一学员 + 同一课程 + 同一自然日只保留一条。

- 当日首次点击：`201`，返回 `{"id":"88","visited_at":"2026-11-01T09:00:00Z"}`；
- 当日重复点击：`200`，返回当天首次那条记录（`visited_at` 不变），不新增行。

规则：课程不存在或已下架 `404 / 10004`；"自然日"按北京时间（UTC+8）划分，入库仍存 UTC。

#### PUT /api/v1/courses/{id}/completion

点亮节点。响应 `200`：`{"course_id":"11","completed_at":"2026-11-01T09:00:00Z"}`。
规则：幂等；已点亮返回原 `completed_at`。

#### DELETE /api/v1/courses/{id}/completion

取消点亮。响应 `204`。幂等。

### 3.4 C4 刷题

#### GET /api/v1/subjects/{id}/practice-paper

取一套组卷（**不含答案**）。响应 `200`：

```json
{ "code": 0, "data": {
  "subject_id": "1", "subject_name": "AI 全栈开发",
  "question_count": 20, "total_score": 200.00,
  "questions": [
    { "id": "3", "type": 2, "title": "下列哪种结构最适合做键值映射查找？", "score": 10.00,
      "options": [{ "option_key": "A", "content": "list" }, { "option_key": "B", "content": "dict" }] },
    { "id": "4", "type": 4, "title": "简述 with 语句的作用…", "score": 20.00, "options": [] }
  ]
}}
```

规则（组卷规则已确认）：
- 每套 **20 题**，按题量比例抽取：判断 20%（4） / 单选 40%（8） / 多选 20%（4） / 简答 20%（4），总数按比例四舍五入后校正为 20。
- 某题型不足时用其他题型补足，**补足优先选客观题**（简答题判分需调用模型，卷内过多会超出判分预算）；整个题池不足 20 题时按实际可用题量组卷，`question_count` 返回实际值。
- 只取 `status=1` 且未删除的题目；每次调用随机抽题，可以重复练习但同一套卷内题目不重复。
- 简答题不返回 `reference_answer`、客观题不返回 `is_correct`。
- 题池为空 `409 / 40001`。

#### POST /api/v1/papers

提交整卷。

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| subject_id | body | string | 是 | 学科 id |
| answers | body | array | 是 | 逐题作答，见下 |
| answers[].question_id | body | string | 是 | 题目 id |
| answers[].option_keys | body | string[] | 否 | 客观题所选选项（判断/单选/多选） |
| answers[].answer_text | body | string | 否 | 简答题作答正文 |

```json
{ "code": 0, "data": {
  "id": "31", "status": 2, "question_count": 20,
  "total_score": 200.00, "obtained_score": 172.00, "pending_count": 0,
  "items": [ ]
}}
```

响应 `202`（判分超过 30 秒，降级为异步）：

```json

```

规则（**同步判分 + 兜底降级**，已确认）：
- 判分在**请求内**完成，整体预算 **25 秒**；`items` 结构与单题字段同 `GET /papers/{id}`。
- 客观题即时判分并写 `exam_answer.is_correct`，多选必须与正确项**完全一致**才得分。
- 简答题逐题调用大模型判分，预算用尽或模型不可用时**按关键词重合度兜底打分**，并在 `ai_comment` 注明；
  因此接口**总能在请求内返回完整结果**，不会产生 `status=1` 的中间态（该状态保留给未来的异步判分）。
- 客观错题写入 `wrong_question`（已存在则累加 `wrong_times`），简答题**不写入**。
- 题目不属于该学科 `400 / 40003`；选项非法 `400 / 40004`；重复提交同一份答卷 `409 / 40002`。

| status | int | 是 | 1 启用 / 0 禁用 |

### 4.8 B6 系统用户（仅超管）

#### GET /api/v1/admin/users

参数：`page`、`page_size`。条目 `{id, username, role, is_builtin, status, created_at}`。

#### POST /api/v1/admin/users

`{username, password, role}`；`role` 1 超管 / 2 运营。重名 `409 / 30002`。响应 `201`。

#### PATCH /api/v1/admin/users/{id}

可改：`password`、`role`、`status`。
规则：内置账号 `is_builtin=1` 不可停用（`409 / 10005`）；不允许把最后一个超管降级（`409 / 10005`）。

#### DELETE /api/v1/admin/users/{id}

内置账号不可删（`409 / 10005`）。响应 `204`。

### 4.9 B7 操作日志

#### GET /api/v1/admin/operation-logs

参数：`page`、`page_size`、`module`、`action`、`admin_user_id`、`start_at`、`end_at`。

## 5. WebSocket

### WS /api/v1/ws/interviews/{id}

连接前需 `POST /interviews/{id}/ws-tickets` 取 ticket，握手时通过 `Sec-WebSocket-Protocol` 子协议头传递（URL 不带凭证）：`new WebSocket(url, ['yunshu.v1', ticket])`。

| 方向 | 消息 | 说明 |
|---|---|---|
| C→S（二进制） | 音频分片 | 16kHz/16bit 单声道 PCM，每帧 100–200ms |
| C→S（文本） | `{"type":"start","question_index":1}` / `{"type":"stop"}` | 控制录音起止 |
| S→C | `{"type":"question","question_index":1,"text":"…","audio_url":"…"}` | 推送当前题目；`audio_url` 为 TTS 音频的短时签名地址，可为空 |
| S→C | `{"type":"partial","text":"…"}` | 实时转写中间结果 |
| S→C | `{"type":"final","text":"…"}` | 该段最终转写 |
| S→C | `{"type":"asr_error","code":70003,"message":"…"}` | 识别失败，可重试 |

**服务端到腾讯云的上游链路（两段式）**

浏览器只连我们自己的 WS，音频由后端转发到腾讯云实时语音识别，浏览器永远拿不到腾讯云凭证：

```
浏览器 ──PCM 分片──> 我们的 WS ──转发──> 腾讯云 ASR WS（wss://asr.cloud.tencent.com/asr/v2）
浏览器 <──partial/final── 我们的 WS <──识别结果── 腾讯云 ASR WS
```

- 上游鉴权：TC3-HMAC-SHA256 对 `SecretId / Timestamp / Expired / VoiceId` 签名，参数拼在上游 URL 上，**仅服务端可见**。
- 连接粒度：每道题一条上游连接，`start` 时建连、`stop` 或超时后关闭，避免跨题串音。
- 引擎：`16k_zh`（中文普通话 / 16k），音频规格 16kHz、16bit、单声道 PCM，与上行分片一致。
- AI 提问播报（TTS）走同一个 AppId 的通用语音合成，按题生成音频后在 `S→C` 的 `question` 消息里带 `audio_url`（短时有效签名地址），前端直接播放。

规则：连接鉴权失败 `1001` 关闭；会话结束由服务端主动关闭；音频**不入库**，只保留转写文本（落 `interview_question.answer_text`）。上游识别失败返回 `70003`，前端可重试同一段音频。
