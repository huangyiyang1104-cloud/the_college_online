## 1. 背景与目标

### 1.1 项目背景

面向互联网学员的在线学习平台，把"学、练、面"三件事串成一条闭环：学员进入学科后按课程节点图顺序看课（课程视频均来自 B 站，平台只做跳转），用学科题库自测，用 AI 面试检验技能掌握情况并拿到面试报告。平台侧由运营人员零代码维护全部内容。

### 1.2 目标用户与诉求

**学员（C 端）**

- 是谁：想转行或进阶的互联网从业者、在校生、自学者；来自开放互联网，非机构内部学员。
- 诉求：知道"学什么、按什么顺序学"；低成本拿到体系化视频内容；能验证自己是否真的掌握，而不是"看完就算学过"。
- 典型场景：选学科 → 沿课程节点图逐课学习并点亮 → 组卷刷题自测 → 临求职前做 AI 面试摸底 → 回看错题复盘。

**运营人员（B 端）**

- 是谁：平台自身的运营/教研团队。
- 诉求：低成本搭建与维护内容（学科、课程、题库、面试资料）；不依赖研发就能上新方向。
- 典型场景：新建学科 → 按学习顺序录入课程与 B 站链接 → 导入或录题 → 上传面试资料 → 上线。

### 1.3 业务目标

让学员形成"选方向 → 学课程 → 刷题自测 → AI 面试检验 → 复盘"的可闭环、可度量的掌握度提升链路；让运营侧零代码维护内容。

### 1.4 验收标准（首期"做成了"的定义）

1. **闭环可演示**：一个学员能完整走完"选学科 → 看课程节点图 → 学课程并点亮（跳 B 站）→ 整卷刷题 → AI 面试 → 看报告 → 复盘错题"全流程，无阻死链路。
2. **技术能力可验收**：语音面试链路、AI 判分等关键技术点能跑通并能被清晰讲清（含评测效果）。

不以用户规模为验收目标。

## 2. 角色与权限

| 角色 | 权限范围 |
|---|---|
| 学员 | 登录后访问全部 C 端功能；除登录/注册页外，所有页面均需登录 |
| 运营 | 管理内容：学科与课程、刷题题库、面试资料库（含检索测试） |
| 超管 | 运营的全部权限 + 系统用户管理 |

- 运营主体为**单一机构自营**，无租户/机构维度，内容全局公共、学员共享。
- 后台仅"超管 / 运营"两种固定角色，**不设独立角色管理模块**，权限按模块级拦截即可。
- 学员账号以**手机号**为唯一标识。**注册**需手机号 + 短信验证码 + 自行设置密码；**登录**为手机号 + 密码。

## 3. 领域结构与术语

```
学科（如 AI全栈开发 / Agent开发 / Java开发）
 └─ 课程（学习路径上的节点，带学科内学习顺序 sort_order，关联 B 站视频链接）

刷题范围 = 学科（整学科一个题池）
AI 面试范围 = 学科（以该学科的检索关键词聚合检索条件，从面试资料库检索片段生成题目）
```

- **不再有「阶段」与「学习路线」两层**：学科本身就是一条学习路径，课程按顺序线性排列，学完由学员自行点亮节点。
- 刷题题库挂载在**学科**上；面试不使用结构化题库，改由面试资料库检索片段生成题目。资料库不按学科归档，**学科只作为检索条件**（不是切片的属性）。
- 课程可上架/下架；内容录完即上线，**无审核流**。
- 删除学科时，若其下仍有未删除的课程，则禁止删除（提示先删除或下架课程）。

## 4. 功能需求 · 学员前台（C 端）

### 4.1 注册登录

- **注册流程**：填写手机号 → 获取并校验短信验证码 → 设置密码 → 完成注册。手机号作唯一账号，已注册手机号需拦截。
- **登录流程**：手机号 + 密码。登录成功后方可访问其余功能；未登录访问一律拦截并引导登录。
- **验证码通道（已定）**：使用**阿里云号码认证服务的「测试手机号码」能力**，短信真实下发到该服务的测试号码、不产生费用；项目全程使用测试号码，不切换真实计费通道。
  - **白名单限制**：只有已加入测试号码名单的手机号可以获取验证码；其余号码在发码环节直接拒绝并提示"当前仅支持测试号码"，不发起阿里云调用。
  - 验证码由**服务端生成**（模板变量 `${code}` 需调用方传入），经阿里云下发后明文只存 Redis、5 分钟有效，校验通过即删除；不落 MySQL。
  - 仍需发送频控与防刷：同一手机号 60 秒内不可重发、单日上限 10 次（沿用 API 设计取值）。
- 密码找回不在首期范围。

### 4.2 首页

- 入口页，区块构成：欢迎区（问候 + 面试快捷入口）、学习方向卡片（学科 + 该学科点亮进度）、继续学习（第一个未点亮的节点）、最近学习（最近访问的课程）。
- 首页只做聚合展示，不新增业务动作。

### 4.3 学科与课程节点图

- 学员选择学科 → 进入该学科的学习路径页，看到按学习顺序线性排列的**课程节点图**（节点 = 课程）。
- 点击节点跳转到 B 站观看；回到平台后由学员自行**点亮**该节点。
- "推荐下一课"= 顺序中第一个未点亮的节点，页面高亮提示。
- 已下架课程不在节点图中展示；学员已有的访问记录与点亮状态不因下架而失效。

### 4.4 学习与进度

- **访问流水**：点击节点跳转时记录访问记录；同一学员 + 同一课程 + 同一自然日（北京时间）只保留一条，当天重复点击不重复记。
- **点亮状态**：由学员手动点亮某个课程节点（= 标记该课已完成），不再有"整阶段完成"概念。
- **学科完成率** = 该学科已点亮课程数 ÷ 该学科课程总数。
- 进度数据按"学员-课程"维度保存，学科维度由课程完成状态实时聚合。

### 4.5 刷题

- 入口：选择**学科**进入刷题，从该学科题池组一套整卷。
- 题型：判断题、单选题、多选题、简答题。
- **整卷模式**：一次组一套卷，学员全部作答后一次性提交；提交后返回整卷结果与得分，可回看历史答卷。
- 判分规则：
  - 判断题/单选题/多选题：按标准答案即时判定对错，并展示解析。
  - 简答题：题库录有**参考答案 + 解析（评分要点）**；由 **AI 对照参考答案**对学员作答打分并给出点评，产出为"得分 + 点评"，不设客观对错。
  - 提交后**同步等待判分**：正常情况一次请求直接返回整卷结果（含学员作答、参考答案、AI 点评与评分要点）；判分超过 30 秒时结果页降级为"判分中"，随后自动刷新补齐。
- 组卷规则：每套 **20 题**，按题量比例抽取（判断 4 / 单选 8 / 多选 4 / 简答 4）；某题型不足时用其他题型补足，整个题池不足 20 题则按实际可用题量组卷；每次随机抽题，同一套卷内题目不重复。
- 整卷**不限时、不限重做次数**，学员可反复练习。

### 4.6 错题本

- 只收录**客观题**（判断 / 单选 / 多选）：答错即入本，后续重做**答对则自动移出**。
- **简答题不进入错题本**，其得分与点评只保留在答卷结果中。
- 支持在错题列表内直接重做：判断 / 单选为单选，多选可勾选多个，提交后判定。
- 错题本按学员隔离。

### 4.7 AI 面试

- 入口：学员选择**学科**发起面试，系统从该学科的资料库中检索出 **5 道题**。
- **出题链路（RAG）**：资料以 Markdown / PDF 上传 → PDF 经 MinerU 等工具转成 Markdown → 按标题层级与语义切分成片段 → 向量化入库；抽题时对学科关键词做**向量召回 + 关键词召回**，用 **RRF 融合排序**取 TopN 片段，交给模型生成 5 道面试题。因此不存在人工维护的结构化面试题库。
- **切片不携带学科元数据**：学科只是检索时的查询词，同一片段可被多个学科命中复用；资料库不按学科划分，也不提供按学科统计。
- 作答方式：**语音作答与打字作答双通道**，可在每道题内自由选择；两种方式的作答进入同一套评分与报告。
- 追问：每题允许 AI 追问，**每题最多追问 1 次**；追问与否由 AI 根据作答质量决定。
- 单场时长约 **15 分钟**；学员**每日最多发起 3 次**面试。每日额度按**北京时间自然日**重置，**发起即计一次**，中途断线或提前退出不退还。
- 面试过程与结果需落库，可回溯；报告需标注每题的来源文档与作答方式。

### 4.8 面试报告

- 报告顶部展示**总得分**：各题得分求平均并四舍五入取整（百分制），未作答题目记 0 分。
- 报告正文为**逐题明细**：每道预问题给出本题得分 + AI 点评，点评需覆盖追问表现。
- 不设分维度评分、不设薄弱知识点、不设提升建议。

### 4.9 简历面试

- 入口：C 端**独立一级入口「简历面试」**，导航顺序为 首页 / 刷题 / AI 面试 / **简历面试** / 错题本 / 学习记录 / 我的；与学科面试并列，不做成学科面试页内的一块。
- 上传：仅支持 **PDF** 简历，单份不超过 10 MB；文件由服务端上传至 **OSS**，系统只保存对象地址、文件信息与解析状态。
- 处理链路：从 OSS 取回 PDF → 转 Markdown（MinerU 等）→ 切分 → 向量化，存入**该学员的个人简历库**（与公共面试资料库隔离）。
- 出题：围绕简历内容做 RAG 检索，**重点针对简历中的项目经历**；共 5 题，其中项目相关不少于 3 题，其余覆盖技能与求职意向。
- 作答与报告：复用学科面试的双通道作答（语音 / 打字）、每题限追 1 次、单场 15 分钟与每日 3 次限制；报告需标注每题来源（来自简历的哪一段项目或技能）。
- 重新上传简历会替换旧简历，旧简历的切分与向量索引同时失效。
- 删除：学员可主动删除自己的简历，删除后文件、切分与向量索引一并清除；历史面试记录保留（不随简历删除而消失）。
- 隐私：简历属于个人信息，**仅学员本人可访问与使用**；管理后台不提供简历原文与解析内容的查看入口。

### 4.10 记录与个人信息

- 学习记录：访问流水 + 节点点亮状态 + 学科完成率。
- 面试记录：历史面试列表，可进入查看对应报告。
- 个人信息管理：查看与修改个人资料（可改字段待确认）。
- 学员的"掌握情况"由学员自行在上述页面查看，平台不额外提供独立的掌握度页面，后台也不提供任何学员掌握度展示。

## 5. 功能需求 · 管理后台（B 端）

| 模块 | 说明 |
|---|---|
| 课程内容（学科 / 课程） | 同一页面按「学科 → 课程」两级维护：学科可新增、**编辑**、上下架，并维护**检索关键词**（供 AI 面试取题）；学科下维护课程标题、说明、时长、**学习顺序**与 **B 站播放地址（完整视频链接）**，课程可**编辑**、拖动调整顺序；下架后 C 端不展示但历史数据保留 |
| 刷题题库管理 | 按学科维护四类题型；客观题录标准答案，简答题录**参考答案 + 解析（评分要点）**；支持新增、**编辑（题干 / 答案 / 解析 / 分值）**、删除 |
| 面试资料库 | 只管理**原始资料**：上传 md / pdf，PDF 经 MinerU 等工具转 Markdown 后按标题层级切分并向量化入库；列表展示文档、类型、大小、上传时间与处理状态（待处理 / 转 md 中 / 已入库 / **解析失败**），失败可**重新处理**，其余支持删除；提供 RRF 混合检索测试用于验证出题效果 |
| 资料导入 | 刷题题库与课程数据用 Excel 模板批量导入；解析后先预览校验结果，确认后入库 |
| 学员管理 | 查看学员列表（手机号、昵称、注册时间、点亮课程数），支持启用 / 禁用账号；不展示刷题与面试结果 |
| 系统用户管理 | 维护后台账号并指定角色（超管/运营）；**内置超管账号不可删除、不可停用** |
| 操作日志 | 记录后台关键操作（记录范围待确认） |
| 数据看板 | 仅统计学员规模与活跃：注册数、新增趋势、日/周活跃 |

- 后台所有内容模块均为"上架/下架"两态，无草稿与审核流；资料上传后统一走导入预览，录完即上线。
- 学科与课程属同一棵树的两层，**不拆成两个独立菜单**，避免对同一份结构做重复维护；课程顺序在同一页面内调整。
- 看板**不做**任何刷题统计、不做任何学员掌握度展示、不做题目错误率排行。

## 6. 明确不做清单

| 不做项 | 原因 |
|---|---|
| 阶段层级与学习路线编排 | 改为「学科 → 课程」线性节点图，不再有中间层 |
| 支付、会员、单课购买、权益校验 | 全站纯免费 |
| 多机构入驻 / 租户隔离 | 单机构自营 |
| 独立角色管理模块、按钮级权限 | 固定两角色，模块级拦截足够 |
| 内容审核流（草稿/待审） | 运营即自己人，录完即上线 |
| 未登录浏览（访客试看） | 全部页面需登录 |
| 站内视频播放、观看时长与完播采集 | 课程仅跳转 B 站 |
| 面试报告分维度评分、薄弱项、提升建议 | 报告仅总分 + 逐题点评 |
| 看板中的学习进度、刷题质量、面试数据指标 | 已收窄为规模与活跃 |
| 题目错误率排行等运营侧内容质量统计 | 后台不展示掌握度类数据 |
| 后台查看 / 管理学员简历原文 | 简历属个人信息，仅本人可见 |
| 第三方登录、密码找回 | 首期不做 |

## 7. 待确认项

以下均为落地细节，不阻塞文档评审，需在开发前定量：

1. **面试超时与断线**：超时未答、断线重连的具体交互；超时后是否允许继续作答（计次规则已定为发起即扣、不退还）。
2. **资料库切片数量下限**：每学科至少命中多少个片段才能支撑 5 题不重复出题，命中不足时的降级方式。
3. **操作日志范围**：记录哪些操作、是否需要保存变更前后内容。
4. **记录保留周期**：学习记录与面试记录保留多久（已定：学员不可自行删除）。
5. **个人信息可改字段**：手机号是否允许修改。
6. **验证码规则**：有效期（暂定 5 分钟）与图形验证码是否需要（通道与频控已定：阿里云号码认证测试号码、60 秒重发、单日 10 次）。
7. **导入校验规则**：重复题目判定口径、答案格式非法与播放链接为空的拦截方式（错误行导出方式已定：接口返回错误列表、前端导出 CSV）。
8. **切分与检索参数**：片段长度与重叠量、切分是否依赖标题层级、TopN 取值、RRF 常数 k、是否在融合后追加 rerank。
9. **面试题生成方式**：由检索片段直接生成题目，还是先聚类主题再按主题配额出 5 题（影响题目重复率）。
10. **简历解析异常**：非 PDF、超大文件、扫描件（无文字层）解析失败时的提示与重试方式；是否允许保存多份简历并选择其中一份发起面试。
11. **简历存储与清理**：OSS 存储区域与加密方式、访问签名有效期；学员删除简历后，向量索引与历史面试记录的清理策略（删除入口已定）。

## 8. 假设项（如无异议按此推进）

1. 学习记录与面试记录长期保留，不提供学员主动删除。
2. "掌握情况"不建独立页面，由学员通过"学科点亮进度 + 答卷结果 + 错题本 + 面试报告"自行查看。
3. 简答题判分以题库中的参考答案与解析为准，AI 不引入外部知识补充评分。
4. 学科完成率以课程点亮状态实时计算，不做冗余存储。

## 9. 风险登记（已知并接受）

| 风险 | 现状 | 影响 |
|---|---|---|
| 简答判分一致性受参考答案质量影响 | 判分以题库的参考答案与解析为锚点 | 参考答案写得越粗，AI 给分越不稳定；同一答案两次提交仍可能有小幅波动，60% 错题阈值存在临界抖动 |
| 语音面试链路复杂度最高 | 首期即上语音 + 打字双通道，语音链路同步落地 | 语音识别、语音合成、打断、超时、并发与面试业务逻辑同期调试；双通道还需保证两种作答进入同一套评分口径，首期闭环周期风险最高 |
| 运营侧无内容质量数据 | 看板仅规模与活跃，无任何刷题统计 | 运营无法定位"哪些题错误率高/题目太难"，只能人工抽查内容质量 |
| 注册受限于测试号码白名单 | 验证码走阿里云号码认证的「测试手机号码」，真实下发但不计费 | 只有白名单内的号码能完成注册与演示，换人或换号需先在阿里云控制台添加；白名单与本地配置需保持一致，否则会出现"前端放行、云端拒绝"。仍需 60 秒重发与单日 10 次频控防刷 |
| 出题质量依赖资料与切分 | 面试题由资料库检索片段动态生成，无人工结构化题库兜底 | 资料质量差、切分粒度不当或检索命中不准时，题目会偏离学科重点或重复；效果调试从"改题"变成"调切分与检索参数" |
| 简历包含个人隐私信息 | 简历上传至 OSS 并切分入库 | 需严格控制访问权限与签名有效期；学员删除简历时必须同步清理向量索引与相关面试记录，否则存在信息残留 |
